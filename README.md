# Прогноз дослушивания треков на Yambda-50M

Задача — предсказать, дослушает ли пользователь хотя бы половину трека, который он запустил из рекомендаций. Сравниваю CatBoost на ручных признаках, автоматическое построение признаков (AutoFE) и Transformer по истории событий. Для всех моделей использую одни и те же треки и метки.

## Результаты

В основном эксперименте 42,9 млн событий от 9000 пользователей. На тесте 1 110 396 прослушиваний от 6323 пользователей.

| Модель | LogLoss ↓ | ROC-AUC ↑ | NDCG@10 ↑ |
|---|---:|---:|---:|
| CatBoost, 98 ручных признаков | 0,47924 | 0,81663 | 0,75569 |
| CatBoost, все 224 признака AutoFE | 0,47738 | 0,81818 | **0,75701** |
| CatBoost, 126 признаков после отбора | 0,47951 | 0,81656 | 0,75491 |
| HistoryGlobal | 0,45672 | 0,83528 | 0,73203 |
| Смесь HistoryGlobal и отобранного AutoFE | **0,45489** | **0,83682** | 0,74203 |

В основном сравнении HistoryGlobal снизил LogLoss относительно отобранного AutoFE на **4,75%**. Разница составила −0,02279. Парный 95% bootstrap-интервал по пользователям лежит от −0,02720 до −0,01878. При этом NDCG@10 снизился на 0,02288. Здесь NDCG@10 оценивает порядок уже проигранных треков в днях с обоими исходами. Значения сначала усредняются по дням каждого пользователя, потом по пользователям.

Отбор сократил набор с 224 до 126 признаков. Доверительный интервал разницы LogLoss с ручным набором из 98 признаков включает ноль. Среди запросов, у которых в доступной истории есть прошлое прослушивание того же трека, контекст сети сохраняет такое событие в 31,6% случаев. ## Данные и протокол

Для пары пользователь–трек беру первое прослушивание за день среди всех источников. Строка попадает в выборку, если это прослушивание началось из рекомендаций. Метка равна 1 при дослушивании от 50%. Короткие прослушивания дают реальные отрицательные примеры. Для признаков сохраняю все доступные события выбранных пользователей, включая дни без обучающих примеров.

Обучение идёт на днях 30–209. На днях 210–239 выбираю параметры моделей, на днях 240–269 — группы признаков и вес смеси. Подбор использует только development-группу. Итоговые метки относятся к отдельной группе пользователей на днях 270–300. Их ранние события могут участвовать в обучении. Все 1000 пользователей первого эксперимента V1 исключены из V2.

Для прослушивания считаю момент доступности исхода как время запуска плюс оценка фактической длительности и 5 секунд. Признаки дня `d` используют события с `available_day < d - 1`. Текущую долю дослушивания модель не получает. Перед чтением тестовых меток сохраняю веса моделей и прогнозы для всех кандидатов.

Это оценка отклика на уже начатое прослушивание. Исходная выборка Yambda ограничена активными пользователями, а тест охватывает один месяц. [Датасет](https://huggingface.co/datasets/yandex/yambda/tree/dd6f3a19eef5866e346c3270e098baa641a44948) · [Подробности протокола](reports/v2/README.md)

## Модели

- **Ручные признаки.** Счётчики и доли по пользователю, треку, исполнителю, альбому и парам с пользователем. Окна 7 и 30 дней и вся доступная история. Дополнительно учитываю давность событий, лайки и дизлайки.
- **AutoFE.** Добавляю агрегаты для окон 2, 3, 10, 14, 60 и 90 дней и экспоненциальных затуханий. При отборе групп фиксирую параметры и число деревьев ручного CatBoost. Отобраны признаки с полураспадом 3 дня и с окном 60 дней.
- **HistoryGlobal.** Сеть кодирует историю один раз на пользователя и день. При оценке трека внимание взвешивает события с учётом кандидата. В контекст попадают последние 256 событий и до 256 событий из более ранней истории. Модель также получает 37 глобальных статистик.

## Запуск

Основной прогон выполнен на A100 80 GB. Подготовка данных заняла 18 минут, подбор и обучение моделей — 70 минут. Для повторения нужен Linux с CUDA и Python 3.12.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r reports/v2/run/requirements-gpu.lock
make download
make test
make v2-reproduce OMP_NUM_THREADS=16
```

`make download` загружает фиксированную ревизию данных и проверяет SHA256. `make v2-reproduce` пишет новый запуск в `reports/v2/reproduce`. [Команды по этапам, проверка прогнозов и восстановление весов](reports/v2/README.md)

Основной эксперимент выполнен на NVIDIA A100 SXM4 80 GB. В нём 42 906 083 события, 1 787 611 обучающих записей и 1 110 396 тестовых записей от 6323 пользователей. Серверный запуск прошёл 158 тестов и 91 проверку аудита. [README проекта](../../README.md) · [Полный отчёт](run/REPORT.md) · [Аудит](run/audit.json)

При этом user-macro mixed NDCG@10 ниже: **0.73203 против 0.75491**, Δ CI **[−0.02506; −0.02072]**. Это выигрыш в вероятностном прогнозе с потерей качества внутридневного ранжирования. Отбор AutoFE не подтвердил улучшение над Manual; AllAuto показал небольшой вторичный выигрыш. Точные числа и оговорки — в отчёте.

## Новая отложенная выборка

Все 1000 пользователей v1 исключены. Используются оставшиеся 9000 пользователей Yambda-50M с полными доступными историями. Разделение по UID фиксируется до чтения исходов: 1000 development, 8000 confirmation. Train берёт ранние примеры обеих групп; tune/select — только development, test — только confirmation. Это оценка будущих исходов с доступной прошлой историей; наличие supervised train-строк у каждого test-пользователя не гарантируется. Итоговый период по-прежнему дни 270–300: датасет не содержит более позднего календарного режима.

Случайное распределение по UID применяется внутри опубликованного набора. Авторы Yambda предварительно отобрали пользователей с не менее чем десятью целевыми действиями в первые десять месяцев и хотя бы одним действием в последующий период. Выводы относятся к этой популяции активных пользователей. [Статья Yambda, § 3.3](https://arxiv.org/html/2505.22238v1#S3.SS3)

Прежнее отсутствие убедительного эффекта нельзя исправлять повторным подбором по старому test. Новая когорта даёт новые target labels. Оценка мощности для небольшой прежней разницы мотивирует 8000 confirmation-пользователей, но не гарантирует мощность для неизвестной разницы history–AutoFE. Все полноразмерные выводы останутся условными на наблюдаемом месяце, политике рекомендаций и выбранной популяции.

Основная задача сохраняется: вероятность дослушать ≥50% первого воспроизведения user–item за день, условно на рекомендованное начало. Кандидаты и исходы одинаковы у всех методов; искусственных negatives нет. Availability и дневной embargo те же, что в v1. Полные истории хранятся даже для дней без supervised query.

## Модели и контроль сравнения

- Manual CatBoost и независимо настроенный AllAuto получают одинаковую сетку из трёх конфигураций.
- AutoFE выбирает группы окон/decay при **фиксированных параметрах и числе деревьев лучшего Manual**. Так устраняется прежняя неоднозначность между добавлением признаков и изменением learner.
- До трёх различных случайных комбинаций того же количества групп выбираются по фиксированному RNG; совпадения с селектором допускаются, но не перерисовываются по качеству. При единственной возможной комбинации контроль один.
- HistoryGlobal: общий Transformer encoder для user-day, 2 слоя, 64/128 hidden units, отдельное candidate-conditioned внимание и exact-ID gates. Raw history содержит item/artist/album, тип события, прошлую долю прослушанного, источник и время. Текущие outcome отсутствуют. Модель по умолчанию имеет около 14,5 млн параметров.
- 512 токенов: 256 последних и до 256 равномерно распределённых по более ранней доступной истории. Это явная компрессия. AutoFE агрегирует всю историю; тождество сохранённой информации не заявляется.
- HistoryGlobal также получает 37 фиксированных population-marginal признаков Manual. Это устраняет отсутствие самого глобального контекста у pure-history модели. AutoFE может порождать дополнительные глобальные временные признаки, поэтому полная эквивалентность глобальных представлений не заявляется.
- PureHistory и модель без межсобытийного encoder — абляции с унаследованными параметрами и одним seed. Последняя сохраняет возраст событий и не является «историей без времени».
- Hybrid смешивает logits AutoFE и History; вес выбирается на select по прогнозам тех же итоговых ансамблей, а не по одному seed.

Основные семейства усредняются по трём seed. Primary comparison — **HistoryGlobal − SelectedAutoFE по row-weighted LogLoss**, парный bootstrap по пользователям, 5000 повторов. NDCG и остальные сравнения вторичны. Дополнительный day-block bootstrap 3/7 дней и ежедневные разности показывают чувствительность к общим временным шокам; это не joint two-way интервал.

Bootstrap пересэмплирует пользователей с уже вычисленными прогнозами. Состояние скользящих глобальных агрегатов фиксировано, в том числе вклад событий других пользователей, доступных к моменту прогноза. Интервал отражает вариацию по пользователям при фиксированном состоянии агрегатов и моделях.

## Защита итоговых исходов

`queries.parquet` не содержит test labels, текущих ratio или duration; `test_labels.parquet` отделён. На этапе search файл читается потоком для проверки SHA256, без декодирования целевых значений. Все модели и параметры фиксируются до предсказания test. Затем сохраняются **все** слепые прогнозы и их хеш в `prediction_lock.json`. После записи фиксации evaluate декодирует labels и рассчитывает метрики. Полные исходные события позволяют обновлять историю для последующих test-дней.

V1 source и результаты не изменены; v2 живёт в отдельном Python namespace `recsys_history_v2`.

## Ресурсы

H100 не обязательна. Полный запуск использует A100 SXM4 80 GB, PyTorch 2.8.0+cu128, CUDA 12.8, driver 595.91.07, BF16, 16 потоков и контейнер с лимитом host RAM около 233 GiB. Подготовка заняла 18,1 минуты; наблюдаемый пик RAM — около 31 GiB. Поиск и финальные fit заняли 69,6 минуты; ранняя остановка выбрала первую эпоху. Размер подготовленных таблиц и контекстов — около 3,3 GiB. Полные временные границы и дополнительные диагностики отражены в [execution provenance](run/execution_provenance.json); пересекающиеся таймеры нельзя складывать в billing time.

В [профиле на реальном train](run/gpu_profile.json) наиболее крупная заявленная модель с ranking auxiliary: 14 517 179 параметров, 100 измеренных шагов после 10 warm-up, 0,0436 с/шаг, пик allocated VRAM 0,69 GiB. Короткая экстраполяция — 2,97 минуты на train-эпоху; это не полный замер эпохи и не гарантия стоимости всего эксперимента. Валидация, AutoFE, аудит и ввод-вывод измеряются отдельно. Карта на 24 GB даёт достаточный запас по памяти для текущего batch; её скорость этим замером не установлена. Практичная конфигурация для повторения: 64–128 GB RAM, ≥50 GB свободного SSD и совместимая CUDA GPU.

## Запуск на сервере

Из корня копии репозитория, Python 3.12, на CUDA-сервере. Для повторения предусмотрен [отдельный конфиг](../../configs/v2_reproduce.yaml): те же научные параметры и UID, новые каталоги. Основной `configs/v2.yaml` описывает уже завершённый и заблокированный запуск.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r reports/v2/run/requirements-gpu.lock
source .venv/bin/activate
export PYTHONPATH=src
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=16
python scripts/download_data.py
python -m recsys_history_v2.run --config configs/v2_reproduce.yaml --phase preflight
python -m pytest -q
python -m recsys_history_v2.run --config configs/v2_reproduce.yaml --phase prepare
python scripts/profile_v2_gpu.py --config configs/v2_reproduce.yaml
python -m recsys_history_v2.run --config configs/v2_reproduce.yaml --phase search
python -m recsys_history_v2.run --config configs/v2_reproduce.yaml --phase evaluate
python scripts/diagnose_v2_seeds.py --config configs/v2_reproduce.yaml
python scripts/diagnose_v2_memory.py --config configs/v2_reproduce.yaml
python -m recsys_history_v2.run --config configs/v2_reproduce.yaml --phase report
python scripts/audit_v2_results.py --config configs/v2_reproduce.yaml
```

Lock [requirements-gpu.lock](run/requirements-gpu.lock) фиксирует фактически использованное Linux/CUDA окружение. [runtime_environment.json](run/runtime_environment.json) содержит версии и сведения об оборудовании. При несовместимости CUDA нужно выбрать подходящую официальную сборку PyTorch **до регистрации выполнения**, записать runtime environment и повторить технические проверки. GPU-зависимости Linux отличаются от macOS; `requirements-v2-macos.lock` — точное локальное окружение smoke. `requirements-v2.txt` — общий локальный вариант и не описывает GPU-окружение основного запуска.

Установка использует `pip`, поскольку lock обращается к PyPI и CUDA-индексу PyTorch. Стратегия `first-index` по умолчанию в `uv` ограничивает версии первым индексом с таким именем пакета. [Документация uv](https://docs.astral.sh/uv/concepts/indexes/#searching-across-multiple-indexes)

Не перезапускайте закончившийся confirmation с изменёнными решениями. Для повторения задайте в копии YAML новые `study`, `processed_dir` и `output_dir`, сохранив научные параметры; не используйте старый каталог с блокировками. Это повторение на той же когорте, а не ещё одна независимая подтверждающая выборка. Fixed seeds, хеши и сохранённые веса позволяют проверять исполнение протокола; побитная идентичность нового обучения на другом CUDA-окружении не гарантируется.

Технический [smoke](../../configs/v2_smoke.yaml) использует только UID из основной development-группы, периоды 120–209, маленькую модель и малый бюджет. Аудит smoke прошёл 77 проверок без пропусков и ошибок.

## Проверка сохранённого результата

В `run/` сохранены исходные blind/final predictions, immutable locks, метрики, графики, completed seed/memory diagnostics и журналы. [Снимок исполнения](run/frozen_sources/) побайтово совпадает со всеми записями frozen source map. [Примечание](run/source_snapshot_note.json) поясняет служебные AppleDouble-файлы, появившиеся при переносе с Mac. Первоначальный аудит сохранён в `audit_initial.json`; финальный аудит отдельно распознаёт binary metadata при проверке неизменности V1 и продолжает проверять весь полный hash set V2. Прогнозы и научная процедура не менялись.

При повторной проверке локально прошли **160 тестов**. Все тестовые ключи и метки V2 заново восстановлены из сырого журнала и совпали построчно. Архивный снимок подтверждает версию исходников на A100. В текущем `run.py` добавлены блокировка перезаписи завершённого запуска и проверка связи с регистрацией перед поиском и итоговой оценкой. [Журнал повторной проверки](run/recheck.log)

Все **23 финальных checkpoint** упакованы в `artifacts/v2_frozen_models.tar.gz` с manifest и SHA sidecar. Архив можно проверить без PyTorch и без распаковки; восстановление путей выполняется из корня репозитория:

```bash
python scripts/package_v2_models.py --verify
tar -xzf artifacts/v2_frozen_models.tar.gz
```

Большие публичные raw/prepared таблицы являются восстанавливаемыми кешами и не входят в компактную поставку. Независимый полный аудит выполнен на сервере с ними и всеми весами; компактная копия при отсутствии этих таблиц явно пропускает соответствующие проверки. Полные прогнозы и доказательства исходного аудита сохранены. Архив весов и большие кеши исключены из Git; при передаче только Git-репозитория их нужно приложить отдельно либо воспроизвести.

Повторную проверку сохранённых прогнозов можно запустить из корня с отдельным путём для результата. Оригинальный серверный `audit.json` остаётся свидетельством полной проверки на A100.

```bash
python scripts/audit_v2_results.py --config configs/v2.yaml --output /tmp/recsys-v2-recheck.json
```
